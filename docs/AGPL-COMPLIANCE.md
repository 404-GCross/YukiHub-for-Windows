# AGPL-3.0 合规说明

本项目整体按 **GNU Affero General Public License v3.0**（AGPL-3.0）授权，全文见根目录 `LICENSE`。

本文说明我们如何履行 AGPL-3.0 的各项义务，以及在发布新版本前必须检查什么。

## 为什么是 AGPL 而不是 GPL

Android 版 YukiHub 使用 GPL-3.0，而本项目的代码基线来自使用 AGPL-3.0 的 LunaBox。
GPLv3 第 13 节允许把 GPL-3.0 作品与 AGPL-3.0 作品组合成整体，组合体按 AGPL-3.0 分发。
反向不成立：一旦使用了 LunaBox 代码，本项目就不能停留在 GPL-3.0。

因此：**本项目可以继续开源，但不再保留闭源或商业双授权的空间。**

## 义务与履行方式

| AGPL-3.0 条款 | 要求 | 本项目如何满足 |
| --- | --- | --- |
| 第 4 节 | 分发时保留版权声明、许可证全文、免责声明 | `LICENSE` 与 `NOTICE` 随仓库与安装包分发 |
| 第 5(a) 节 | 显著声明已修改并给出日期 | 根目录 `NOTICE` + `docs/upstream-lunabox.md` 的修改记录 + git 提交历史 |
| 第 5(b) 节 | 声明整体按本许可证发布 | `NOTICE` 与 `README.md` |
| 第 5(c) 节 | 整体按 AGPL 授权，不得附加额外限制 | 仓库不含附加条款；不接受禁止再分发的 CLA |
| 第 5(d) 节 | 交互式界面须展示 Appropriate Legal Notices | 设置页提供"关于与开源许可"面板 |
| 第 6 节 | 分发二进制时提供对应源代码 | 源码托管在公开仓库；安装包中附带 `LICENSE`、`NOTICE`、`THIRD_PARTY_LICENSES.md` |
| 第 13 节 | 通过网络交互的用户有权获得源码 | 应用不提供对外服务；如将来提供联机服务或自建更新服务，需在服务页面提供源码获取方式 |

## 分发检查清单

每次发布二进制前逐项确认：

- [ ] `LICENSE`（AGPL-3.0 全文，不得修改）随安装包分发
- [ ] `NOTICE` 随安装包分发，且修改日期已更新
- [ ] `THIRD_PARTY_LICENSES.md` 与 `third_party/` 目录随安装包分发
- [ ] 应用内"关于与开源许可"面板可见且指向正确的仓库地址
- [ ] 安装包中的版本号与源码 tag 一致（对应源代码可精确定位）
- [ ] `docs/upstream-lunabox.md` 的修改记录已更新到本次发布
- [ ] 第三方依赖许可证审计已通过（见 `THIRD_PARTY_LICENSES.md` 第四节）
- [ ] 若本次引入了来自 Android 版 YukiHub（GPL-3.0）的代码，
      对应文件已保留其原始版权声明与许可证说明

## 源码获取

对应源代码即本仓库。若你通过二进制获得本软件，可在 `README.md` 中找到仓库地址；
若仓库地址失效，请通过 Android 版 YukiHub 的社区渠道联系维护者。

## 常见问题

**能否把本项目用于商业用途？**
可以。AGPL-3.0 允许收费分发与商业使用，但必须遵守上述义务，尤其是提供对应源代码。

**能否把本项目闭源？**
不能。

**能否把本项目与闭源模块组合？**
AGPL-3.0 第 5(c) 节要求整体按本许可证授权。将闭源模块与本项目链接为一个程序并分发，
会违反该条款。独立进程、通过公开协议通信的情形需单独评估。

**Android 版（GPL-3.0）与桌面版（AGPL-3.0）之间能否互相搬运代码？**
可以，方向为 GPL-3.0 → AGPL-3.0 时最清晰；反向搬运需要原始著作权人授权。
无论哪个方向，都必须保留原文件的版权声明。
