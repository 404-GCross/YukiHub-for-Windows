# ADR-0002：数据权威源与同步后端

- 状态：已采纳
- 日期：2026-09-28
- 决策者：YukiHub 项目组
- 相关：[ADR-0001](0001-fork-lunabox-as-windows-baseline.md)、
  [mobile-yukihub-migration.md](../mobile-yukihub-migration.md)

## 背景

阶段 2（领域模型统一与双向数据迁移）需要冻结两端的数据契约，但
`mobile-yukihub-migration.md` 第七节留了 4 个待决策问题，其中两项会阻塞实现：

1. 桌面端与 Android 版同时在线时，谁是冲突裁决者？
2. 桌面端是否复用 Android 版的自建同步服务器（`/api/sync/*`）？
3. 桌面端是否保留自有的云同步（上游 `cloudsync` 的墓碑与脏表机制）？
   它与 Android 版的哈希比对是**两套算法**，不能长期并存。
4. 元数据缓存是否沿用 Android 版的 `VnMetadata` 字段？

已确认的事实：

- Android 版已有自建同步服务（`/api/sync/*`），属于本项目自有，不属于上游 LunaBox。
- 桌面端继承了上游的 `internal/service/cloudsync`（墓碑 + 脏表），
  与 Android 版的哈希比对机制在冲突裁决上是两套独立实现。
- 上游 LunaBox 的默认云备份后端是第三方托管服务（Umbra），
  本项目已把默认值改为 WebDAV（用户自持存储），见 ADR-0001 与 CHANGELOG。

## 决策

### 1. 数据权威源 = Android 端

Android 版是本项目既有的、数据已经沉淀的一端，桌面版是后来者。因此：

- **schema 5 快照格式是权威契约**，桌面端数据模型向它对齐，而不是反过来。
- 冲突时**以 Android 侧为准**。
- 桌面端独有的能力若 Android 无对应字段：
  - **不得**写入同步快照（否则 Android 侧无法理解，会丢数据）
  - 只能作为桌面端本地字段保留
  - 例：桌面端的 `want_to_play` 状态导出到 Android 时降级为 `unplayed`
- 桌面端新增字段前，先确认 Android 侧是否有承接位置；没有就走"本地字段"路径。

### 2. 同步后端 = 本项目自有的服务器（Android 版已在用的 `/api/sync/*`）

- 桌面端对接**我们自己的**同步服务，即 Android 版已在使用的那套。
- **不接上游 LunaBox 的第三方托管服务**（Umbra 等）。
- 前置条件（服务端侧确认后才能开工）：
  - 服务端需接受桌面端客户端（版本、User-Agent、协议版本）
  - 需明确桌面端的 client 标识，避免与 Android 客户端互相覆盖
- 用户自持的 WebDAV 备份（阶段 3 验收 5）**保留**，它与"我们的服务器"不冲突：
  前者是用户自己的存储，后者是本项目提供的服务。

### 3. 冲突裁决算法 = 收敛为一套，以 Android 侧（哈希比对）为准

- 长期目标：只保留一套实现。既然权威源是 Android 端，
  保留的是 **Android 版的哈希比对**。
- 上游 `cloudsync` 的墓碑/脏表机制属于要被替换掉的实现。
- **在服务落地之前**，`cloudsync` 仍需维持可用（它支撑现有的云备份功能），
  但不得再往里加新的、Android 侧无法理解的语义。
- 严禁两端各写一份合并算法长期并存——这是"一次导入能用、
  持续同步后出现重复条目"的根因。

### 4. 元数据缓存结构 = 沿用 Android 版的 `VnMetadata` 字段

沿用 Android 侧结构，便于两端共享缓存，也避免桌面端发明第二套字段名。

### 5. 服务器相关工作整体排后

所有依赖服务端的工作（同步服务对接、AI 游玩报告、社区与好友等）
统一排在工作序列后部，集中到路线图的**阶段 6**。

## 影响

- 阶段 2 的**文件级导入导出不受影响**，可以先行——它不依赖任何服务端。
- 阶段 3 的 WebDAV 用户自持同步保留原位。
- 阶段 4 中依赖服务端的项目（AI 游玩报告、社区与好友）移至阶段 6。
- 阶段 2 的"冲突裁决收敛为一套实现"这一验收项，**实际落地时间与服务端对齐**，
  在阶段 6；阶段 2 只完成"契约与文件级迁移"。

## 后续动作

- [ ] 服务端确认接受桌面端客户端（版本、UA、协议）
- [ ] 确定桌面端 client 标识
- [ ] 阶段 6 开工时，先移除上游 `cloudsync` 的墓碑/脏表，改用哈希比对

## 未决事项

- 服务端当前协议版本与桌面端需要协商的细节，留到阶段 6。
- 是否需要支持"桌面端离线期间产生的数据"与服务器的合并窗口策略。
